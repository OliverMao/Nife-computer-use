---
title: 'Get started with nife-computer-use'
description: 'Install the extension and complete a first checked desktop action.'
---

This tutorial installs the extension, verifies Windows helper setup, and completes a first observation-and-action loop.

## 1. Install the extension

```bash
nife install npm:nife-computer-use
```

Use `nife install -l npm:nife-computer-use` to scope the package to one project instead of the whole user profile.

Start Nife in an unlocked interactive Windows desktop session. Nife runs the Windows helper, a small executable that speaks UI Automation. The helper is installed per user at `~/.nife/agent/helpers/nife-computer-use/windows-bridge.exe`; the prebuilt binary ships with the package and is installed on first use, so the package has no install-time scripts.

Inside WSL, run Nife exactly the same way. WSL interop starts the Windows helper as a Windows process, so nife can drive Windows UI while your shell, files, and repository stay in Linux.

## 2. Check the active configuration

Run this command inside Nife:

```text
/computer-use
```

The response shows whether browser access and strict background execution are enabled, along with the source of each configuration file.

## 3. Ask the agent to inspect an app

Open a simple app such as Calculator or Notepad, then ask Nife:

```text
find the app's window, inspect its visible controls, and tell me what you can act on. don't change anything yet.
```

The agent first calls `find_roots`, then `observe_ui`. The observation returns a `stateId` and element refs such as `@e12`; those refs belong to that immutable state.

## 4. Ask for one checked action

Give the agent a small action with an observable result, for example:

```text
click the 7 button and verify that the display shows 7.
```

The agent acts from the observed `stateId` and attaches the expected result to `act_ui`. A successful action returns the next state, often as a compact diff. The agent should use that returned state directly rather than immediately observing again.

You now have a working desktop loop. Use the generated [agent state and action contract](../reference/agent/contract.mdx) for state, batching, browser, and fallback behavior, or the generated [tool schema reference](../reference/agent/tools.mdx) for exact parameters.
